Week 37 / 2026

Dieser Inhalt ist noch nicht in deiner Sprache verfügbar.

7 – 13 Sep 2026 · 64 commits · release cut

Prefix histogram — 8 feat: · 27 fix: · 23 docs: · 6 chore:.

Mig asked whether the smoke tests were still meaningful. The answer was no, and finding out took the rest of the week.

The Playworks canary had not run since 30 May — a hundred days — because it was triggered by a cloud deploy workflow that also last ran on 30 May, deploys having moved to a laptop since. It was not red. It was not amber. It reported nothing, and nothing is what a healthy canary also reports. A canary whose trigger depends on who deployed is the wrong shape once a laptop is a deploy path.

That is the week’s subject, and once it had a name it turned up in eleven more places. The version-drift probe compared served versions against a gitignored 'dev' stub, so it abstained on every comparison — and abstain renders as nothing to report, which is indistinguishable from current. The journal publication check compared the working tree against the working tree, the one surface where the answer is always yes. jin cloud ls printed synced on the basis that an object with that key exists — not a hash, not a size, not a date. The Bell cleared rings because a source returned an empty list, when the source had been handed no tables to look at.

A probe that reads a surface where the failure cannot appear. By Friday the phrase was being used as a diagnosis, and by October it had become the sentence the whole security regime turns on. This is the week it got named.

The probes were lying

Section titled “The probes were lying”

Sister-1 spent most of the week on this, and the sequence is worth following because each fix exposed the next layer.

She re-pointed the dark canary at a schedule on the Monday. On the Tuesday it ran zero tests and looked fine doing it — the job’s condition was an allow-list keyed to the deploy event, which is null on a schedule, so it skipped, reporting completed and neutral having executed none of its thirty-six tests. Worse than the dark canary it replaced, and the exact shape I have spent the week removing from other people’s probes. Changed to a deny-list, with the polarity written down as the rule rather than the fix.

Then the tenant matrix turned out to have collapsed to one leg, because a default value is always truthy on a manual dispatch: I verified a matrix by using the one trigger that disables it. And once it genuinely fanned out, ten of thirty-six tests had never been able to run — the summary said “24 passed” and nothing anywhere said that a third of the suite had sat out.

Two “flakes” chased properly rather than retried: suspended machines, cold first-byte at 1.85–2.29s against 0.27–0.31s warm. A wake step was added and the 30-second timeout deliberately left alone, because raising it would hide the regression the canary exists to catch.

Among the things the revived probes then found:

  • A smoke script dead since 2 August on an empty-array expansion under macOS’s bash 3.2 — the shell CLAUDE.md names. Running again, it immediately found something better: a flat route never establishes the tenant catalog context, so every query failed, and a .catch(() => ({})) turned that into an empty map. The error an author saw read this column is not Typology-typed while the table had 460 rows of types. An author told that would debug their own selector for an hour. I did — twice.
  • A canary spec red for three weeks behind two blindfolds, where fixing either one alone would not have surfaced it.
  • The publish smoke claimed seven proofs and delivered six. The closing line announced all seven; step six had silently skipped. That commit also carries the week’s genuine milestone — the cloud authoring loop proven end to end for the first time, a draft staged in one store arriving as a commit on the tenant’s remote, verified with git ls-remote rather than the push’s own word. That is the shape this whole week has been about, and my own script did it on its first real outing.
  • W36’s journal was written, generated, and never published, while the check said the site was current for two days.

Two silences that were clearing real alarms

Section titled “Two silences that were clearing real alarms”

Two of the week’s findings were not reporting-layer problems. They were changing answers.

The Bell cleared rings nobody had checked. Auto-clear rested on an inference — the source ran, looked, and found nothing — which only holds when the source could look. A lean build purges the silver tables at finalization, so the next incremental build handed the validity source no tables at all: not clean data, no data. It returned an empty list, indistinguishable from an all-clear, and the aggregator cleared two rings covering roughly 2,800 genuinely invalid rows. A crashing plugin cleared its rings the same way. The fix gives a source three outcomes instead of two — rings, nothing, or abstained — and makes the aggregator’s rule positive: a ring clears only when its own source ran to completion this build. Surfaced on the way, and worse in its way: the diagnostic source had never produced a ring in its life, because it ran before the table it reads was baked, and returned empty silently, forever.

A KLS could not survive its own filename. DuckDB derives a catalog name from the file name and dbt emits fully-qualified view DDL, so the filename is baked into the stored SQL of every view — and views re-bind at query time. Rename it, which is all a snapshot is, and every view names a catalog that no longer exists. Measured: all seventeen KLS files on the machine carried filename-bound views, and in the snapshots they were already dead. The lean pass had known and worked around it rather than removing it. Normalization now runs at the end of every build, identifying the qualifier structurally so the same logic repairs a file renamed long ago — which is what lets a separate script reach snapshots already on disk. Repairing a snapshot mutates something we call immutable, so that stays a deliberate script rather than automatic.

The fleet gets ruled, and the record charges interest

Section titled “The fleet gets ruled, and the record charges interest”

Mig studied the fleet deck on the 10th and gave a run of rulings. The ones that stuck: presences, not tenants, are what gets registered — a tenant is an identity, only a presence has a place, and the register records a decision rather than a discovered fact. Cohort, Organisation and Site replace three invented words, because a facet is identified by membership cardinality, not shape. One store per installation. No fleet identifier.

Two days earlier the routing citizen had narrowed from five fields to two, and the decisive evidence was one row of the live file rather than anything in the paper: two hosts serve no tenant at all and disagree on the auth flag — so a flag present where there is no tenant cannot be a tenant property, and is not routing either. One of the two fields leaving was one sister had argued to keep; Mig asked “is this the right move?” and it does not survive the question. The test it leaves behind is reusable: if the same tenant is served by two hosts, must the answer be the same? Yes, the tenant owns it. No, the host owns it. Routing owns neither.

Then the papers had to catch up, and this is the part worth recording. Mig ruled on the 8th and the resolver shipped the same day. Three decks, two at public addresses, still called it the top open item two days later — charging interest, and holding a finished branch. One of them contradicted itself on the same public page. The correction says plainly that the second half of the deck’s own proposal was wrong.

The same pattern caught a second sister: her own freshly-written spec was carrying a question Mig had answered the day before. Which is the drift this whole fortnight has been about, and it would have been mine this time.

And one retirement turned out to be a slogan. “No fleet identifier” was never a column — grepping finds two cautionary comments — so retiring it meant declining to add one, which made the argument sound braver than it was. The surviving claim is narrow: no row carries the fleet it belongs to. And it is a deadline rather than a verdict — the discriminator returns the moment rows from two installations share a table, which is now written into the migration verb as a refusal rather than a comment, because a precondition nobody executes is a footnote.

A constant wearing the shape of logic

Section titled “A constant wearing the shape of logic”

Every material on the SAP IS-H tenant read as billable — 12,331 of 12,331 — because one extractor line wrote the literal string "true". That source system’s material master carries no billability field at all, and 1,632 findings of a reimbursement-gap signal rested on it, with nothing anywhere saying so. The line below it was worse: a conditional whose both branches returned "true". A constant wearing the shape of logic.

Two problems, and only one of them a judgement call. An extractor inventing bytes at the trust boundary is settled by the zero-transform rule and simply stops. What a model does with genuinely unknown billability is a declaration, and now lives in the config cascade with an engine default of exclude — absent means refuse. That tenant declares billable and keeps its 1,632 findings, now withdrawable in one line. The data carries both facts side by side, so the assumption never overwrites the fact.

The companion finding is a layering fault, and it is in the journal because the author got it wrong first. A metering model reads zero rows on that tenant, and the security review had read that as a thin feed. It is not: 25,930 movements, every department code filled, 48 cost centres. Both causes are ours — the inflow side filters on a word that source system never emits, and the outflow side inner-joins a mapping only the other source system delivers. She proposed relaxing the filter and offered 167 extra rows on the real-data tenant as an acceptable cost. Mig asked why that tenant should be affected at all. The 167 were stock corrections, eight to twenty-two rows per department over three years. That tenant’s number was right and my predicate was loose. So the commit is a spec rather than code, and it is blocked on a question only the customer’s expert can answer — is that tenant’s issue a ward delivery or a store receipt? One line apart in the dispatch, very far apart in meaning, and if it is a receipt the coefficients would be confidently wrong, which is worse than empty.

Smaller, and worth noting

Section titled “Smaller, and worth noting”
  • The security review landed, and is the reason several other things in this week look the way they do: 108 agents, eleven subsystem slices, four lenses, 29 findings confirmed of 32 — seven critical, fifteen security. Held local rather than pushed, because it carries live-exploit detail on production surfaces. The number becomes load-bearing immediately: it is what the new roadmap’s first phase repays, what the status deck’s what is wrong right now slide states, and the reason five decks ship unlisted and noindexed.
  • There was no roadmap. Five partial ones, no dates, and a missing-for-production document still describing the shipped cloud concept as future work — the doc predates its own subject. Now there is one, with a spine (by year-end someone who is not Mig runs a tenant on their own data, and nothing about that is dangerous), four phases, and every item carrying a done-when that names evidence. Mig’s call to be fully open on stage was taken: zero customers, seven criticals, a scheduled lockout — because a pre-customer product with no findings has not been looked at, while one with findings and a repayment date has. And the bottleneck is stated honestly because the repo shows it either way: decision latency, not build throughput. One unruled question held a finished resolver for weeks while 423 commits landed around it.
  • The Typology reconciler learned to follow a rename. The gate matched source to Gold by name only, while its own error message told authors to cite the source — and nothing ever read the citation back. Four tenants had fully typed their ingestion side, 110 declarations, and reconciled zero columns. Not forgetfulness: their pipelines rename, and the gate could not express that shape. Scope kept narrow on purpose — only value-preserving operations reconcile by type equality, because a cited aggregate legitimately changes the type. Two further corrections in the same commit, both the same family: a failure whose printed explanation came out blank, unactionable by construction; and a probe that reported a refutation about something it could not see, now reporting unverifiable instead. The owner ratified all three: a failure that cannot state its reason is a defect, not strictness — the same rule as no-silent-defaults, turned on the gate itself.
  • The bottom-right corner had three tenants and no owner. Found by the revived canary on production, measured in a real browser: a transient chip overlapping a persistent control, and a hit test at the chip’s centre returning the other component. A person could not open linked windows. The point fix shipped first; then the structural one, because the cause is the absence of an owner, not either component — three things claimed the same corner independently and nothing coordinated them. The new coordinator measures each participant rather than hard-coding offsets, because the heights depend on font and zoom, and a fixed offset is exactly how this comes back.
  • The DMG shipped that morning could not start. Mig asked what a tester does with it. The launcher script — which ships inside the bundle — invoked two verbs retired a fortnight earlier, and the rename sweep had missed it because nothing reads it. The user is told “JinDesk did not start within 30 seconds” with no hint that a verb is the problem. Three more walls behind it, including a config template shipped entirely commented out, failing the very next check. The new gate extracts every invoked verb and asks the CLI itself whether it answers — a machine surface, not a list to maintain.
  • Asking which engine you were talking to required the right to run one. Two read-only verbs were classified as builds by fall-through, and a third was not a verb at all — the joke being that the refusal message lists the allowed verbs, which made typing a wrong verb the only way to learn the right ones. Version now answers twice, deliberately: while that was being written, the app served one version and the worker reported one twelve patch releases behind. One number would have hidden that.
  • All eleven syncable tenants were stale, 21 to 38 days, every one reporting synced. Found by answering Mig’s question about two of them. Three states now, with two choices stated: unknown is not fresh, because saying synced for a check we did not perform reintroduces the defect one layer down; and a parse failure returns nothing rather than zero, because epoch-zero would read as 1970 and report everything stale — the same lie pointing the other way. A slack window, because a tool that accuses you the moment you comply trains you to ignore it.
  • A map rendered nothing for weeks because a schema name was compared as a string value where it is only valid as a quoted identifier. Valid SQL, no error, a truthful empty set for a question asked wrong, and the one caller wrapped in a catch. The tileset was fine the whole time — 193,094 features. It cannot be caught where it happens, so it is caught at the source instead, by a test that also asserts it still matches something, so it cannot quietly stop watching.
  • The sync script said the clean sisters had landed when nothing had. A bare “(failed)” on the other refs was a ref transaction rolling back — one stale lease takes the whole batch. The comment in this script asserted the opposite, and the error message repeated the assertion to the operator. Both were wrong in the same direction, which is the dangerous one: it reads as partial success.

Zero note: commits, zero test: commits, zero refactor: commits. The first is the salon migration completing in practice; the second is tests arriving inside the fix that needed them, which is where they belong.

Almost every fix: body this week is a confession, and that is not a tone — it is what the week’s findings were made of. “I broke the ship”, and the self-diagnosis that she had searched three places for a coverage gate and never looked in tests/. “I verified a matrix by using the one trigger that disables it.” “And I got it wrong first, which is why the paper exists.” Two sisters each finding they had fixed the instances and left the class. A review retracted before its recipient could act on it. A paper whose premise had dissolved rather than been contradicted.

The connective tissue is one question asked in nine different places and answering differently each time: what does this thing’s silence mean? For a canary, a drift probe, a cloud listing, a Bell source, a reconciler and a coverage gate, the answer all week was not that it looked and found nothing but that it never looked. The fix was the same shape every time, and it is never to widen the gate: make the two states distinguishable. Abstained is not clean. Unverifiable is not a mismatch. Unknown is not fresh.
